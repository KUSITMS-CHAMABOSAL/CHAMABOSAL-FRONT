# 프로젝트 규칙 점검

코드를 수정하지 않습니다. `pnpm lint`가 잡는 의존 방향과 import는 린트 결과로 확인하고, 여기서는 린트가 잡지 못하는 위반을 봅니다.

## 현재 변경

- 파일: !`git status --short`
- 통계: !`git diff HEAD --stat`

## 순서

1. 범위를 정합니다. 인자가 파일이면 그 파일, ref면 `git diff <ref>...HEAD`, 없으면 `git diff HEAD`.
2. 변경 파일에 해당하는 `.claude/rules`의 규칙를 읽습니다. 직접 읽은 규칙만 근거로 씁니다.
3. 아래 항목을 규칙과 대조해 실제 위반만 보고합니다.

## 점검 항목

- 레이어 역할: `pages`의 조회·mutation, `entities`의 상태 변경, `shared`의 도메인 지식
- TDS에 있는 컴포넌트를 직접 만들거나 감싸기만 한 래퍼
- 경로 문자열 직접 사용, 라우트로 만든 시트·다이얼로그, 자체 뒤로가기 버튼
- 인라인 스타일, `cn` 없이 이어붙인 클래스, 앱 코드의 Emotion, 다크 모드 스타일
- 진입 직후 자동 바텀시트, 권한 거부 시 멈추는 기능, `intoss-private://` 링크
- 해요체가 아닌 문구, [취소]로 쓴 다이얼로그 왼쪽 버튼
- 스펙 없이 추측한 API, 확인 없이 결정한 🔖 항목

## 출력

- `위반`과 `확인하지 못한 것` 두 섹션으로 나눕니다.
- 위반마다 `파일:라인`, 심각도(높음/중간/낮음), 근거 규칙, 문제와 영향, 고치는 방법을 적고 심각도 순으로 정렬합니다.
- 위반이 없으면 "위반 없음"과 확인하지 못한 항목만 적습니다.

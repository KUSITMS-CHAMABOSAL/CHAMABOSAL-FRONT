# 커밋

## 현재 변경

- 파일: !`git status --short`
- staged: !`git diff --staged --stat`

## 순서

1. 범위를 정합니다. 인자가 있으면 그 범위만, staged 변경이 있으면 staged만, 없으면 전체 변경을 봅니다.
2. `git diff`(staged면 `--staged`)로 실제 내용을 읽습니다. 파일명만 보고 판단하지 않습니다.
3. 형식은 `{type}: {한국어 설명}`이고, 무엇을 했는지 짧게 씁니다. 예: `chore: 프로젝트 기본 설정`, `ui: 하단 탭바`
4. 한 커밋에는 한 type만 담습니다. 기능 로직과 시각 작업이 섞이면 `feat`와 `ui`로 나눕니다.
5. 커밋마다 메시지 한 줄, 포함할 파일, `git add`와 `git commit -m` 명령을 보여줍니다.

| type       | 용도                                    |
| ---------- | --------------------------------------- |
| `feat`     | 새로운 기능 추가                        |
| `fix`      | 버그 수정                               |
| `chore`    | 설정, 빌드 스크립트, 패키지 의존성 관리 |
| `docs`     | README, AI 지침과 스킬, 문서 변경       |
| `style`    | 코드 포맷팅 (동작 영향 없음)            |
| `refactor` | 동작 변경 없는 구조 개선                |
| `ui`       | 화면·컴포넌트의 시각 작업               |

## 지키는 것

- 사용자가 커밋 실행을 명시적으로 요청한 경우에만 `git add`, `git commit`을 실행합니다.
- 커밋 전 lint-staged가 스테이징 파일에 `eslint --fix`, `prettier --write`를 실행하고, commitlint가 형식과 type을 검사합니다(`commitlint.config.js`). `git commit --no-verify`로 우회하지 않고 코드나 메시지를 고칩니다.
- 커밋 메시지에 AI 도구 표기(`Co-Authored-By`, `Generated by`)를 남기지 않습니다.
- 검증하지 않은 변경은 커밋 전에 확인할 항목으로 따로 적습니다.
- `.env*`, `.claude/settings.local.json`처럼 공유하면 안 되는 파일이 포함되면 제외하라고 알립니다.

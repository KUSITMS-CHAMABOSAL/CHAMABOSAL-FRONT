# 인터랙션

정해진 도구는 없습니다. 인터랙션이 사용자에게 무엇을 느끼게 해야 하는지부터 정하고, 그 목적을 WebView에서 가장 싸게 끊김 없이 달성하는 방식을 고릅니다. 단순하게 풀리면 단순하게 풉니다. 기준 예시는 이마 톡톡(`features/vote/tapForehead`), 공양미 가득(`widgets/certification/potFull`), 오늘의 보살들 캐러셀(`widgets/home/todayBosals`)입니다.

## 1. 목적과 시안 범위 정하기

구현 전에 아래 다섯 줄을 사용자에게 보여주고 합의합니다. 시안에 모션이 없으면 제안으로 표시합니다.

- **피드백**: 사용자가 무엇을 눌렀고 결과가 무엇인지 (예: 톡톡 → 링이 울렁이고 숫자가 튀며 짧은 햅틱)
- **상태**: 애니메이션이 끝난 뒤 남는 화면 상태와 그 상태를 가진 곳 (예: 톡톡 횟수는 `useForeheadTap`의 `count`)
- **입력**: 탭, 드래그, 길게 누르기 중 무엇이고 손가락이 닿는 면적은 얼마인지
- **고정과 움직임**: 원본 그대로 둘 레이어(배경, 빛)와 움직일 레이어를 나눕니다. 공중에 떠 있는 요소는 정지 화면에 그린 움직임일 수 있습니다.
- **끝 화면**: 끝난 화면이 시안의 어느 프레임과 같아야 하는지 정합니다. 중간에 시안에 없는 모양(작게 시작하는 더미 등)이 보이면 미리 알립니다.

시안 자료는 이 순서로 확인합니다.

1. `get_motion_context`로 Figma 키프레임을 읽습니다. 비어 있는 경우가 많습니다.
2. 프레임 이름의 번호(`-01`~`-11`)와 주석(`data-annotations`)으로 단계와 순서를 읽습니다.
3. 프로토타입 영상을 받으면 `scripts/contact-sheet.sh <영상> <출력.png> 12 4 <crop>`으로 한 장에 모아 봅니다. 단계가 바뀌는 칸 수로 길이를 잽니다.
4. 움직일 레이어의 SVG에 다른 레이어에 가려진 요소(회색 쉐도우 등)가 있는지 봅니다. 크기나 위치가 바뀌면 드러납니다.
5. 그래도 근거가 없으면 제안으로 표시하고 사용자에게 고르게 합니다.

사용자에게 결과를 보여줄 때는 시안과 나란히 놓은 스크린샷으로 대조합니다.

## 2. 구현 방식 고르기

위에서부터 목적을 채우는 첫 줄을 고릅니다. 고른 이유를 코드 주석이나 PR에 한 줄 남깁니다.

| 방식                            | 맞는 경우                                                                | 비용과 한계                                                   | 예                    |
| ------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------- | --------------------- |
| CSS transition                  | 두 상태 사이 전환, 진행률 표시                                           | 끝나는 시점을 알기 어려움                                     | 톡톡 초록 교차 페이드 |
| CSS keyframes (`@theme inline`) | 마운트 시 한 번, 반복 강조. 순서만 다르면 지연을 CSS 변수로 넘김         | 요소마다 다른 값(방향, 거리)을 넣기 어려움                    | 순위 차례 등장        |
| 가로 스크롤 + scroll-snap       | 넘겨 보는 캐러셀, 페이지 넘기기. 드래그·관성·멈출 자리를 브라우저가 처리 | 손가락을 따라 돌리거나 늘리는 자유 제스처는 못 함             | 보살 인증 캐러셀      |
| Web Animations API              | 요소마다 값이 다르거나, 끝난 뒤 상태를 바꾸거나, 다시 재생해야 함        | ref가 필요하고 완료 처리를 직접 함                            | 링 울렁임, 쌀알 낙하  |
| 라이브러리 (`motion` 등)        | 손가락을 따라가는 자유 드래그, 스프링 물리, 레이아웃 간 공유 요소 전환   | 번들 증가, 의존성 추가는 사용자 확인. TDS 내부 motion은 못 씀 | 없음                  |
| 영상, Lottie                    | 디자이너가 만든 길고 고정된 연출(축하, 온보딩)                           | 상태 조합을 표현할 수 없음. 용량 큼                           | 없음                  |

라이브러리를 고르기 전에 같은 효과를 scroll-snap이나 WAAPI로 만든 버전의 한계를 먼저 적습니다. 한계가 사용자 경험에 보이지 않으면 라이브러리를 쓰지 않습니다.

## 3. WebView에서 끊기지 않게 만들기

항상 지키는 규칙입니다. 프레임이 튀거나 모양이 이상하면 `references/pitfalls.md`에서 증상으로 찾습니다. 새로 걸린 문제는 그 표에 한 줄로 추가합니다. Tailwind·TDS 스타일 함정은 `.claude/rules/ui.md`에 있습니다.

- **`transform`, `opacity`만 애니메이션합니다.** `width`, `top`, `filter`는 쓰지 않습니다. 감쌀 수 있는 효과는 SVG 내부가 아니라 감싼 `div`에 겁니다.
- **애니메이션마다 감싸는 요소를 나눕니다.** CSS `scale`과 WAAPI `transform`을 같은 요소에 걸면 서로 덮어씁니다.
- **바뀔 그림은 미리 마운트하고 `opacity`로 바꿉니다.** 진행률로 바뀌면 두 장을 겹치고 `opacity-(--progress)`처럼 CSS 변수로 넘깁니다.
- **거리와 크기는 실행 시점에 잽니다.** 기기 높이에 따라 달라지는 값은 `getBoundingClientRect()`로 구해 키프레임에 넣고, 붙어 보여야 하는 요소는 같은 쪽(위 또는 아래)에 고정합니다. 화면 밖까지 번지는 배경은 화면 폭에 비례해 늘립니다.
- **쌓이거나 자라는 표현은 기존 요소를 아래 축으로 키웁니다.** 시작 크기는 보이는 값으로 잡고 끝은 시안 크기(1)로 맞춥니다. 다음 단계는 마지막 조각이 합쳐진 시점에 시작합니다.
- **연타는 막지 않고 받습니다.** 진행 중인 대상은 ref로 제외하고, 상태 변경은 애니메이션 `finished` 뒤에 합니다. 다 끝난 WAAPI는 `commitStyles()` 뒤 `cancel()`해 합성 레이어를 놓아줍니다.
- **`prefers-reduced-motion`을 지킵니다.** CSS는 `motion-safe:`, `motion-reduce:transition-none`으로, WAAPI는 재생하지 않고 바로 최종 상태를 반영합니다.

## 4. 측정

눈으로 "부드럽다"고 판단하지 않습니다. 측정 코드는 매번 새로 쓰지 않고 `scripts/`를 `browser_run_code_unsafe`의 `filename`으로 실행합니다. 옵션은 먼저 `browser_evaluate`로 localStorage에 JSON을 넣습니다.

1. `pnpm dev`를 띄우고 375px 폭으로 엽니다. 배경이 화면 밖까지 번지면 360·430px도 봅니다.
2. **단계 확인**: `interaction-capture`에 `{ dir, count, interval, clip?, tap?, times? }`를 넣고 `capture-sequence.js`를 실행한 뒤, `contact-sheet.sh <dir> <출력.png>`로 한 장만 읽습니다.
3. **프레임**: `interaction-probe`에 `{ ms, reload?, tap?, scroll?, by?, times?, interval?, cpu? }`를 넣고 `measure-frames.js`를 실행합니다. `tap`은 선택자를 누르고, `scroll`은 선택자 요소를 `by`px씩 넘겨요. CPU 4배 감속이 기본입니다.
4. 기준: 33ms를 넘는 프레임 0~1개, 최대 50ms 미만, 끝난 뒤 남은 애니메이션(`runningAnimations`)이 일부러 남긴 것만 있음, 콘솔 에러 없음. 넘으면 3장 항목부터 의심합니다.
5. WebView 렌더링, 햅틱, 실제 프레임은 QR 실기기에서만 확인할 수 있습니다. 확인하지 못했으면 보고서에 미확인으로 적습니다.

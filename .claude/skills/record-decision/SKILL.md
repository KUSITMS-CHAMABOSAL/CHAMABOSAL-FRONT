# 결정과 이슈 기록

문서는 길게 쓰지 않습니다. 두 기록 모두 나중에 같은 논쟁이나 조사를 반복하지 않게 하는 것이 목적입니다.

## 결정 기록

`docs/decisions/NNN-short-title.md`에 씁니다.

- 쓰는 때: 디렉터리 구조·레이어 경계·파일 배치 기준 변경, API client·상태 관리·form·테스트 전략 같은 반복 패턴 결정, 라이브러리 추가나 교체, 기존 규칙의 예외 허용, 다시 논쟁할 가능성이 높은 trade-off
- 쓰지 않는 때: 단순 버그 수정, 오타·문구·스타일 변경, 규칙을 그대로 따른 CRUD 구현, 페이지 내부 구현 세부사항
- 제목은 `# NNN. 결정 제목`이고 섹션은 순서대로 `상태`(`Proposed`, `Accepted`, `Superseded`), `맥락`(문제와 제약), `결정`(한두 문장), `근거`(이유와 trade-off), `대안`(버린 선택지와 이유), `영향`(지킬 기준, 관련 파일)입니다.

## 외부 이슈 기록

`docs/known-issues/short-title.md`에 씁니다.

- 쓰는 때: 디자인 시스템이나 외부 패키지의 값이 Figma·스펙과 다를 때, 서드파티 버그나 앱인토스 플랫폼 제약으로 우회 코드를 넣었을 때, API 스펙과 실제 응답이 다를 때, 미루는 성능·품질 이슈
- 쓰지 않는 때: 우리 코드로 바로 고칠 수 있는 버그, 구조나 라이브러리 결정
- 제목은 `# 이슈 제목`이고 섹션은 순서대로 `무엇이 다른지`(기대값과 실제 값), `어디서 확인했는지`(Figma 노드, 파일 경로, 재현 명령), `왜 지금 우리 코드에서 고치면 안 되는지`, `언제/누가 해결해야 하는지`입니다.

# 리팩토링 (동작 변경 없음)

## 순서

1. 범위를 정합니다. 인자가 없으면 `git status --short`의 변경 파일과 주변 파일만 봅니다.
2. `find-code-location` 스킬과 `.claude/rules/code.md`를 읽습니다.
3. 아래 후보를 찾아 목록으로 먼저 보여줍니다.

| 후보             | 기준                                                         |
| ---------------- | ------------------------------------------------------------ |
| 잘못된 레이어    | 레이어 판별법과 다른 위치                                    |
| 큰 페이지        | `pages`가 배치 외의 로직이나 재사용 UI를 가짐                |
| 반복 UI          | 같은 구조의 JSX가 3번 이상 반복 → 데이터 배열 + `map`        |
| 책임 혼합        | API, 상태, UI가 한 파일에 섞임 → `api`, `model`, `ui`로 분리 |
| 남은 미사용 코드 | 이번 작업으로 쓰이지 않게 된 항목                            |

4. 사용자가 고른 항목만 적용합니다. unused 정리나 같은 폴더 내 이동처럼 좁고 명확하면 바로 적용해도 됩니다.
5. `pnpm lint`와 `pnpm exec tsc -b`를 실행합니다.

## 지키는 것

- 동작, props 이름, 라우트 경로를 바꾸지 않습니다.
- 새 의존성이나 새 추상화를 만들지 않습니다.
- 작업 범위 밖의 죽은 코드는 보고만 하고 그대로 둡니다.

결과에는 바꾼 것, 유지한 동작, 검증 결과, 남긴 후보를 적습니다.

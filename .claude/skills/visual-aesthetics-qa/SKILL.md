# 시각 품질 검증

코드를 수정하지 않습니다. 추측이 아니라 측정값을 보고합니다. 측정하지 못한 항목은 통과로 적지 않습니다.

## 1. 코드 훑기

대상 파일에서 아래를 찾습니다.

- 임의 색과 크기: `#[0-9a-fA-F]{3,8}`, `rgb(`, `-\[[0-9]+px\]`
- `style={{`, 앱 코드의 `@emotion`, `dark:`
- 레이아웃을 바꾸는 애니메이션: `transition-(all|\[?width|\[?height)`, `animate` 대상의 `width`, `height`, `top`, `left`
- `prefers-reduced-motion`(`motion-reduce:`) 대응 없는 반복 애니메이션
- `.claude/rules`의 UI 규칙에 어긋나는 문구, 자체 뒤로가기, 자체 상단 바

## 2. 브라우저 측정

브라우저 도구(Playwright MCP 등)가 없으면 이 단계를 건너뛰고 미확인으로 보고합니다.

1. `pnpm dev`를 띄우고 대상 화면으로 이동합니다. 주소는 `http://localhost:5173`입니다.
2. 뷰포트를 360x640과 390x844로 바꿔가며 각각 측정합니다.
3. 뷰포트마다 `scripts/page-audit.js`를 읽어 함수 부분만 evaluate에 넘기고(첫 줄 주석과 맨 끝 `;` 제외), 결과와 스크린샷을 남깁니다.
4. 콘솔 에러, 실패한 네트워크 요청을 확인합니다.
5. loading, empty, error 상태와 긴 닉네임처럼 깨지기 쉬운 경우를 가능한 만큼 재현합니다.
6. 터치 위주 흐름을 눌러봅니다: 바텀시트 열고 닫기, 키보드가 입력창을 가리지 않는지, 스크롤 끝의 CTA와 safe area.

| 측정값               | 기준                                                           |
| -------------------- | -------------------------------------------------------------- |
| `horizontalOverflow` | `false`                                                        |
| `tinyText`           | 비어 있음 (11px 미만 금지, 검수 기준)                          |
| `colorScheme`        | `light`                                                        |
| `pinchZoomBlocked`   | `true` (지도 같은 예외 외에는 확대·축소 비활성화, 출시 가이드) |
| `inlineStyleCount`   | 앱 코드 기준 0. TDS 내부 요소와 CSS 변수 예외는 제외하고 판단  |
| `smallTargets`       | 44px 미만은 권고 위반. TDS 컴포넌트 내부면 제외                |
| `unsizedImages`      | 비어 있음 (CLS 방지)                                           |
| `unnamedControls`    | 비어 있음 (`aria-label` 필요)                                  |

## 3. 시각 판단

스크린샷을 Figma 시안과 비교합니다. 시안이 없으면 아래만 봅니다.

- 정보 위계: 화면의 주요 행동이 하나로 보이는가. 제목, 본문, 캡션 크기 차이가 분명한가
- 간격: 관련 요소는 가깝고 다른 묶음은 떨어져 있는가. 좌우 여백이 화면 간 일정한가
- 일관성: 같은 역할의 요소가 화면마다 같은 모양인가. TDS 요소와 직접 만든 요소의 톤이 맞는가
- 빈 상태와 긴 글자: 잘림, 겹침, 어색한 줄바꿈이 없는가

## 4. 성능

개발 서버 수치는 믿지 않습니다. `pnpm build` 뒤 `pnpm preview`로 측정합니다.

- 성능 추적 도구(Chrome DevTools MCP 등)로 CPU 4배 감속 상태에서 측정합니다. 기준: LCP 2.5초, CLS 0.1, INP 200ms 이하
- 빌드 로그의 청크 크기와 경고를 확인합니다.
- 출시 가이드 기준: 인터랙션 지연 2초 미만, 반복 호출과 SDK 과다 호출 없음, 네트워크·메모리 급증 없음

## 5. 보고

항목마다 `통과`, `실패`, `미확인`과 측정값을 적습니다. 실패는 파일 위치, 근거 기준, 고치는 방법을 심각도 순으로 씁니다. `출시 차단`(검수 기준 위반)과 `개선 권고`를 나눕니다.

브라우저 측정은 토스 앱 WebView와 다릅니다. 실제 safe area, 내비게이션 바, 키보드, SDK 동작은 QR 실기기 테스트 항목으로 남깁니다. 기준 원문은 https://developers-apps-in-toss.toss.im/checklist/app-nongame.md 입니다.

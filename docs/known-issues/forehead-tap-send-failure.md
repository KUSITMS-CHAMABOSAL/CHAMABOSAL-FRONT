# 이마 톡톡 횟수 전송이 실패하면 횟수가 사라짐

## 무엇이 다른지

- 기대값: 화면을 떠날 때 친 횟수를 보내다가 일시적으로 실패해도(네트워크 오류, 5xx) 횟수를 잃지 않고 다시 보낼 수 있습니다.
- 실제 값: 화면을 떠날 때([종료하기], 뒤로 가기, 닫기) 한 번만 보내고, 실패하면 오류를 버립니다. 화면은 이미 떠났고 횟수도 남지 않아 서버에 저장되지 않습니다. 이미 보냈거나(`TAP_003`) 시간이 지난(`TAP_004`) 경우도 같은 `catch`로 들어가 일시적인 실패와 구분하지 않습니다.

## 어디서 확인했는지

- `src/features/vote/tapForehead/model/useForeheadTaps.ts`의 언마운트 정리 함수 `sendTaps(...).catch(() => {})`
- PR #46 CodeRabbit 리뷰(Major, `useForeheadTaps.ts:38`)
- 재현: `src/app/mocks/handlers.ts`의 `POST /api/rounds/:roundId/taps`가 실패를 돌려주게 바꾼 뒤 `pnpm dev`에서 몇 번 치고 [종료하기]를 누르면, 투표 탭으로 이동하고 횟수는 다시 보내지 않습니다.

## 왜 지금 우리 코드에서 고치면 안 되는지

실패 안내와 재시도 시안이 없습니다. [종료하기]에서 먼저 보내고 실패하면 화면에 남아 토스트로 알리는 방식을 시험했지만, 떠나려는 사람을 붙잡는 흐름이 어색해서 되돌렸습니다. 뒤로 가기나 닫기로 떠나면 화면이 이미 사라져 알릴 곳도 없어서 [종료하기]만 고쳐서는 해결되지 않습니다.

## 언제/누가 해결해야 하는지

- 디자이너와 프론트엔드 담당자가 실패 처리 방식(안내 시안, 재시도 위치)을 정한 뒤 처리합니다.
- 처리하면 위 재현 방법으로 다시 확인하고 이 문서를 지웁니다.

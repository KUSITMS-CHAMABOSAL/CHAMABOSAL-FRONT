# 내 방이 아닌 방 번호의 처리가 화면마다 다름

## 무엇이 다른지

- 기대값: `/rooms/999`처럼 숫자는 맞지만 내가 속하지 않은 방으로 들어오면 모든 방 화면이 같은 방식으로 처리합니다.
- 실제 값:

| 경로              | 지금 동작                                                         |
| ----------------- | ----------------------------------------------------------------- |
| `/rooms/999`      | 서버가 `ROOM_005`, `ROOM_002`를 주면 "사라진 방" 다이얼로그 → `/` |
| `/my/999`         | `me.rooms`에 없으면 표시 없이 `/`로 이동                          |
| `/rooms/999/vote` | 확인하지 않음. 투표 화면이 비어 있어 아직 드러나지 않음           |

정수가 아닌 방 번호(`/rooms/abc`)와 없는 경로는 `RoomTabLayout`과 `*` 라우트에서 404로 통일했습니다.

## 어디서 확인했는지

- `src/pages/home/ui/HomePage.tsx`의 `isRoomGone`, `RoomGoneDialog`
- `src/pages/myBosal/ui/MyBosalPage.tsx`의 `if (!room) return <Navigate to={paths.root} replace />`
- `src/pages/vote/ui/VotePage.tsx` (빈 화면)
- 재현: `pnpm dev` 후 `/rooms/999`, `/my/999`, `/rooms/999/vote`로 들어가 봅니다.

## 왜 지금 우리 코드에서 고치면 안 되는지

투표 화면이 아직 없어 투표에서 어떤 처리가 맞는지 정할 근거가 없습니다. 홈의 "사라진 방" 다이얼로그는 보던 방이 사라진 경우를 위한 화면이라, 처음부터 내 방이 아닌 경우와 같은 화면을 쓸지도 함께 정해야 합니다. 라우트 구조 정리(#29)와 목적이 달라 분리했습니다.

## 언제/누가 해결해야 하는지

- 프론트엔드 담당자가 투표 화면 이슈에서 처리합니다.
- 후보: `RoomTabLayout`에서 `me.rooms`에 없는 방이면 한 번에 404나 `/`로 보내고, 홈의 "사라진 방" 다이얼로그는 보던 중 사라진 경우에만 씁니다.
- 처리 방식을 정하면 세 경로를 다시 확인하고 이 문서를 지웁니다.
